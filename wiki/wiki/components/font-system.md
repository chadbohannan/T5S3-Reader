# Font system

The firmware has three kinds of fonts: built-in fonts compiled into flash, compressed built-in fonts that are inflated on demand, and `.cpfont` files loaded from the SD card. All three reach [GfxRenderer](gfx-renderer.md) by integer font ID. A per-page prewarm pass loads only the glyphs a page needs, because internal heap is too small to hold a CJK font. Synced against T5S3-Reader@`f460af3` as of 2026-11.

## Built-in fonts

`lib/EpdFont/builtinFonts/*.h` are generated by `lib/EpdFont/scripts/fontconvert.py` (`convert-builtin-fonts.sh`) from the TTF/OTF files in `builtinFonts/source`. `src/main.cpp` wraps each in `EpdFont` and groups four styles into an `EpdFontFamily` (regular, bold, italic, bold-italic). Reader families are Noto Serif 12/14/16/18, Noto Sans 12/14/16/18 and OpenDyslexic 8/10/12/14. UI fonts are Ubuntu 10 and 12 (regular and bold) and Noto Sans 8 (`SMALL_FONT_ID`). Building with `OMIT_FONTS` keeps only Noto Serif 14 plus the UI fonts.

A font may be compressed: `EpdFontData.groups` then points at DEFLATE blocks of glyph bitmaps (`EpdFontGroup`: offset, compressed and uncompressed size, glyph count). `FontDecompressor` (`lib/EpdFont/FontDecompressor.h`) inflates groups with uzlib into up to 4 page slots (one per style) of at most 512 glyphs (`MAX_PAGE_GLYPHS`).

## SD-card fonts

`.cpfont` files live in `/.fonts/<Family>/` or `/fonts/<Family>/` with one file per size (`<Family>_12.cpfont` to `_18`). `docs/sd-card-fonts.md` says both roots are scanned and merged, and `/.fonts/` wins on a name collision. Users install them three ways: download on device (`FontDownloadActivity`, Settings > System > Manage Fonts), upload on the [web server](web-server.md) Fonts tab, or copy by hand. `FontInstaller` (`src/FontInstaller.cpp`) handles download and install. The converter is `lib/EpdFont/scripts/fontconvert_sdcard.py`; pre-built fonts are in the `crosspoint-fonts` repository. This repository also ships `SD_fonts/` with Alegreya, Atkinson Hyperlegible Next, Bitter and Source Han Sans SC.

The parts:

- `SdCardFontRegistry` finds families on the card (`discover()`).
- `SdCardFontManager` loads one family at the reader size and registers it with the renderer. Only one SD family is loaded at a time.
- `SdCardFontSystem` (`src/SdCardFontSystem.cpp`, global `sdFontSystem`) ties these to `SETTINGS.sdFontFamilyName`. `begin()` runs at boot and installs `SETTINGS.sdFontIdResolver`, so settings code can map a family name and size to a font ID. `ensureLoaded()` runs before a book opens (from `ReaderActivity::onEnter()`); it re-discovers when `markRegistryDirty()` was called (for example after a web upload) and loads or unloads the family to match settings.
- `SdCardFont` (`lib/EpdFont/SdCardFont.h`) reads glyphs from the file on demand. It keeps per-page glyph data (up to 512 glyphs), a 64-glyph overflow area for misses, a 128-glyph persistent cache, and an advance-width table of up to 768 entries per style for layout. Kerning classes and ligatures are loaded lazily; the full kern matrix is never resident, only a mini matrix for the classes on the current page.

## Prewarm

`FontCacheManager` (`lib/GfxRenderer/FontCacheManager.h`) runs a two-pass render. `createPrewarmScope()` puts it in scan mode; a render pass then records text per font and style instead of drawing glyphs; `endScanAndPrewarm()` loads all needed glyphs at once (inflate groups or read SD glyphs); the second pass draws. Layout calls `renderer.ensureSdCardFontReady()` before measuring words, which builds the advance table from the chapter's words. This trades one extra text pass for far fewer random SD reads and decompressions. The reader flow is in [page render pipeline](../concepts/page-render-pipeline.md).

## Section cache coupling

The section cache stores the reader font ID in its header. Changing family or size gives a new font ID, so every cached chapter is re-laid out on next open. See [SD card layout](../concepts/sd-card-layout.md).
